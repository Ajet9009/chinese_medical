# 草本通 · 架构总览（代码级 mermaid）

> **仓库**：chinese_medical  
> **技术栈**：Vue3(:5174) + FastAPI(:8000) + SQLite + Redis + Neo4j 4.4 + 双 FAISS（实体 / 文献）+ LangGraph + Langfuse + 可选 Milvus/MySQL 长期记忆  
> 节点命名约定：`文件.py::函数()` / 表名 / 开关名  
> 产品思路对齐 grid-qa；**不抄**电网壳（两票、孪生、SCADA、Prometheus 全家桶、知识自进化）。

    R -->|中医| EX["entity_extraction"]
    EX --> NZ["entity_normalization FAISS 实体"]
    NZ --> CG["cypher_generation EXPLAIN"]
    CG --> CE["cypher_executor Neo4j"]
    CE --> DR["doc_retrieval"]

    R -->|非中医| DR

    DR --> R2{_route_after_docs}
    R2 -->|中医或文献有摘录| AG["answer_generation 推 token"]
    R2 -->|非中医且无文献| GR["general_response 推 token"]

## 图 3 · 文献检索引擎 mixed_search

实体 FAISS（口语→标准名）与文献 FAISS（知识库块）是**两套文件**。

```mermaid
flowchart TD
    IN(["search_documents(question,<br/>viewer_dept, viewer_role)<br/>doc_store.py"])
    IN --> EN{"DOC_HYBRID_ENABLE"}
    EN -->|1| MIX["FaissDocStore.mixed_search<br/>dense FAISS + BM25 → rag/rrf.py"]
    EN -->|0| DEN["FaissDocStore.search 仅向量"]
    MIX --> MMR{"MMR_ENABLE"}
    MMR -->|1| M1["rag/mmr.py::mmr"]
    MMR -->|0| KEEP["按 RRF 分截断"]
    DEN --> ACL
    M1 --> ACL
    KEEP --> ACL
    ACL["knowledge_acl.acl_ok<br/>空科室=公开"]
    ACL --> BLK["knowledge_service.blocked_ids"]
    BLK --> OUT(["→ doc_chunks"])
    OUT --> CRAG["pipeline.retrieve_with_crag"]
    CRAG --> G{crag.grade top1}
    G -->|incorrect + 改写开| RW["LLM 改写问句"]
    RW --> MIX2["再 search 一次"]
    MIX2 --> G2{仍 incorrect?}
    G2 -->|是| REF["hits=[] action=refused"]
    G2 -->|否| OK["action=rewritten"]
    G -->|correct/ambiguous| OK2["action=normal"]
```

图谱事实仍可单独作答：文献 CRAG 拒答不等于整题拒答；`doc_rag.should_refuse` 要求图谱也空。

## 图 4 · 短期记忆：LTRIM 条数 vs ContextCompressor token

问答主路径用 [`common/conversation_store.py`](../common/conversation_store.py) + [`common/context_compressor.py`](../common/context_compressor.py)。**不要**和 `_008_memory` 里那套拼 Prompt 的 Compressor 混成一件事。

```mermaid
flowchart TD
    MSG["add_message 落 SQLite"] --> RP["Redis RPUSH + LTRIM<br/>REDIS_HISTORY_MAX 按条"]
    ASK["准备进图"] --> HOT["get_recent_for_llm<br/>优先 Redis LRANGE<br/>失败 hydrate SQLite"]
    HOT --> CC{"CONTEXT_COMPRESS"}
    CC -->|0| CUT["只留 GRAPH_HISTORY_LIMIT 条"]
    CC -->|1| FIT["fit_budget 从最新往旧<br/>塞进 token_budget"]
    FIT --> OV{有溢出旧轮次?}
    OV -->|无| KEEP["只用 kept"]
    OV -->|有| SUM["LLM 摘要 overflow"]
    SUM -->|失败| FB["degraded context_compress<br/>退回 kept 不中断问答"]
    SUM -->|成功| PACK["_pack_with_summary"]
```

- **LTRIM**：热缓存条数硬顶（`REDIS_HISTORY_MAX`，默认 50），不管 token。失败 fail-open 回 SQLite。
- **ContextCompressor（问答）**：决定塞进 LangGraph 的历史有多长。`token_budget` 默认 2000（`TOKEN_BUDGET`）+ `fit_budget` 从最新往旧留；放不下则旧轮次 LLM 摘要。`CONTEXT_COMPRESS=0` 时退回 `GRAPH_HISTORY_LIMIT` 条数截断。系统提示、图谱结果、当前问句不计入该预算。
- LTRIM 不管 token；Compressor 不管 Redis 列表长度。

## 图 4b · 长期记忆（`_008_memory`，失败不挡问答）

与会话 Redis List **不是同一条键**。短期键：`mem:short:{user_id}:{session_id}`。

```mermaid
flowchart TD
    ASK["/ask /ask/stream"] --> RM["main._read_memory<br/>get_context"]
    RM --> LT["Milvus 按 user 检索三元组"]
    RM --> PF["MySQL 画像"]
    RM --> ST["Redis 记忆短期窗口"]
    ST --> FIT["MemoryManager 内 Token 压缩"]
    LT --> CTX["拼到 user_question"]
    PF --> CTX
    FIT --> CTX
    CTX --> GRAPH["LangGraph"]
    GRAPH --> WM["main._write_memory"]
    WM --> USR["add_message user<br/>短期同步 + 异步抽三元组"]
    WM --> AST["add_message assistant<br/>仅短期"]
```

| 层 | 存什么 | 后端 | 隔离 |
|---|---|---|---|
| 短期（记忆子系统） | 本会话刚说了什么 | Redis List + LTRIM + TTL | user + session |
| 长期 | 跨会话稳定事实 | Milvus 三元组；失败 `data/memory/long_term.json` | user |
| 画像 | 结构化偏好 | MySQL `agent_user_profile`；失败 JSON | user |
| 审计 | 变更预览 | MySQL `agent_memory_audit` | user |

问答图用的历史窗口仍是 `conversation_store` 那条 Redis List（会话消息），不要把两套短期记成一个开关。

## 附 C · 闭环总览

> **防胡编**：非中医先检索文献，无摘录才 `general_response`；图谱空 + 文献 CRAG incorrect → `REFUSE_ANSWER`。  
> **记忆**：会话 Redis LTRIM 管条数；`common/context_compressor` 管进图 token；`_008_memory` 管跨会话事实，失败不挡问答。  
> **回流**：点踩 → 黄金集关键词；文献 RAG 另写 `eval/ragas_dataset.json` 五列。  
> **韧性**：依赖失败 `degraded(tag)`，用户侧 fail-open。

**顶层**：JWT 管身份，LangGraph 管图谱问答，`common/rag` 管文献质量，SQLite 管会话与知识登记，obs/Langfuse 管可见性。
